# 制作一个源：给 AI 的工作单

本指南介绍 API v3 源的制作和交付流程。API v3 基础接口适用于 PicaYomi 0.10.6 起；当前模板使用的列表展示配置要求 0.10.8 起，其他能力以契约与 manifest 为准。先读 [AGENTS](../AGENTS.md) 和 [契约](CONTRACT.md)。

## 先形成证据表

在编写适配前记录以下信息，缺失项标成未知，不能凭类似平台猜测。

| 项目 | 必须记录 |
|---|---|
| 平台入口 | 网站与 API 地址、是否可配置、是否需要账号 |
| 列表 | 最新和推荐分别来自哪里、页码/offset/limit、总数或结束条件 |
| 搜索 | 请求方法、关键词编码、响应字段与分页 |
| 详情 | 稳定作品 ID、标题、封面、简介与作者映射 |
| 章节 | 站内稳定 ID、分组、完整分页、显示顺序与番外插入 |
| 图片 | 完整列表、顺序、URL、Referer/必要请求头、格式和失效条件 |
| 可选能力 | 分类、排行、登录、收藏、只读评论、查看回复是否确有接口；不实现发表 |
| 维护证据 | 检查日期、脱敏响应/页面片段、参考实现版本、引用代码的许可证 |

资料输入可以是用户提供的响应、允许访问的公开页面、现有实现或明确许可参考的源代码。当前拷贝实现是案例，不表示其他平台复用同一协议。遇到受限内容或需要登录的接口，保留错误与条件，不绕过访问授权。

## 从模板落地

按 README 设置 `PYSOURCE_KIT`、`PYSOURCE_ROOT`，复制 `templates/api-v3` 为新源目录。修改 manifest 的 ID、名称、作者、发布者和地址；默认模板 ID 不能用于发布。源目录中只放随包发行的 manifest 与 Lua，样例、测试、说明留在目录外。

模板的虚构协议可以先跑通工具链，之后逐项替换：

1. HTTP 请求、状态码与 JSON/HTML 结构检查。
2. 基础列表、详情、完整章节、完整图片列表。
3. 稳定 ID 和所有分页，尤其大作品的第二页及后续章节。
4. 按证据加入推荐、搜索等能力及其断言，再声明支持。
5. 配置、凭据、缓存失效与故障处理。

迭代检查使用新的临时输出目录，例如 `PYSOURCE_OUTPUT="$(mktemp -d)"` 后传 `--out "$PYSOURCE_OUTPUT"`。同一目录中的同版本产物不允许改写；不要为绕过报错删除正式发布文件。

不要把模板的示例地址、字段、图片 URL 或伪造结果当真实实现。所有业务接口返回严格三元组；章节、作品和评论列表使用 items/has_more/next，图片使用 items/complete。SourceError 必须带 code/message/retryable；历史 order 由宿主映射。

## 让后续 AI 易于维护

- 单文件可先放 `main.lua`；复杂时拆为请求、解析等包内 Lua 模块，通过 `ctx.require` 导入。
- 在源对应维护说明中记录字段映射、完整分页方式、已验证能力与已知限制。测试样例只保留断言所需字段。
- 列表信息按当前响应映射；0.10.8 起可用 `list_display` 配置字段顺序和标签、用 `metadata` 保留热度等平台文本。缺字段跳过，不逐本补抓详情；使用新展示能力时声明对应最低宿主版本。
- 可变地址放在 manifest 的 settings 中，以 `ctx.getSetting` 读取；网站、API、图片服务按用途分别处理。
- 发现结构变化时明确报错，不能以空数据覆盖最后有效缓存。缓存通过 `ctx.cache` 隔离使用。
- 不随普通域名变更更换 ID、publisher_id、章节 ID 或数据归属。需要新宿主能力时先说明兼容条件。

## 给 AI 的可复制任务

```text
为 PicaYomi API v3 制作一个新漫画源。
先阅读源开发 README、AGENTS.md、AUTHORING.md、CONTRACT.md、TESTING.md。
平台与可用资料：<页面/脱敏响应/参考实现及版本>
源 ID / 名称 / 发布者：<填写>
需要支持的能力：<只列有接口证据的能力>
账号或网络限制：<填写，没有则明确没有>

先输出请求/字段/能力映射及未知项，然后在源目录实现。
使用模板、SDK、稳定章节 ID；不修改宿主或伪造可用能力。
交付脱敏样例、离线断言、构建与宿主检查的实际结果。
分别记录结构检查、离线解析、真实站点和设备验收；缺条件不得报全通过。
仅本地实现和验证，未经明确要求不发布或部署。
```

新增源须用独立源 ID 通过测试订阅安装，在未改注册表和 UI 的宿主中验证菜单、分类/排行类型及列表。缺少通用交互时明确记录 SDK 缺口，不能用源 ID 条件重写页面。

完成后用 [测试清单](TESTING.md)和 [发布规则](PUBLISHING.md)收尾。
