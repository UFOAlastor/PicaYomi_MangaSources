# 拷贝源案例：怎样把平台证据变成源

案例当前为 copymanga 1.5.0、API v3 / 宿主 0.10.8 起。平台协议沿用既有实现，新增列表字段映射和源声明的展示配置；1.4.0 完成的 v3 迁移继续保留。下文标注 1.3.0 的记录是历史验收，不表示当前版本已完成真实账号验收。当前私有仓库代码在 `extensions/copymanga/`；未来源仓库在 `sources/copymanga/`。以下是已实现方案的说明，不保证平台未来继续沿用相同结构；修改前重新核对响应，不直接照抄域名。

## 能力取舍

目前声明网站账号登录、推荐、最新、搜索、分类、排行、下载、本地收藏及网站账号收藏；仅账号收藏需要登录，匿名浏览和本地收藏保持可用。账号收藏已完成离线回归，真实账号验收仍需有效会话。不声明只读评论；当前站点无评论区，历史章节吐槽端点在当前 API 返回 HTTP 404。所有源均不提供发表评论，不能据此关闭其他源已有的只读评论。没有实现的入口由宿主隐藏。不要因为网站有按钮或其他软件支持就直接开启能力。

## 请求与字段映射

| 链路 | 当前做法 | 核心断言 |
|---|---|---|
| 推荐 | 读取网站首页“漫畫推薦/漫画推荐”区的作品链接与封面 | 仅该区，单页；不得把“最新上架”混入 |
| 最新 | newest 列表，offset=(page-1)*60、limit=60 | 链接提取 path_word，解析分页 |
| 搜索 | 搜索页读取相对 countApi 路径，再请求分页 JSON，limit=12 | 关键词编码，路径不能换成任意 origin；results.list 必须为数组 |
| 分类 | /filter 提取 theme 与名称；/comics 的数据属性解析作品，limit=50，三种站内排序 | 去重分类；正确处理空结果、分页总量、JS 字符串转义；不执行脚本 |
| 排行 | /rank?type=male/female&table=day/week/month/total | 八种类型由源返回，限定榜单区域并合并标题链接；每榜单页 |
| 详情 | 页面标题、封面、作者、标签、简介 | 稳定作品 ID 与必需标题/封面 |
| 章节 | 优先同一网站章节接口；登录阅读只使用网站会话 | 认证失败不退回匿名接口 |
| 匿名兼容接口 | 未登录且网站读取失败时，保留旧 App 分组及章节分页 | 验证 offset 与总量；绝不携带网站 token |
| 图片 | 按稳定 UUID 从 App API 或网页章节取得完整列表 | App 返回 uuid 匹配、size 与 contents 数一致，网页数据非空 |

这些路径与字段是当前实现快照，不是通用 API。网页兜底可能使用公开页面中的协议参数，不应推广为跳过平台授权的机制；受限标记必须保留失败语义。

### 列表信息（1.5.0）

2026-10-22 公开页面核对：最新页每个 `.exemptComic_Item` 带作者链接，排行榜每个 `.ranking-all-box` 带作者和热度文本；分类数据的 50 条抽样全部有 `author/status`。此前只提取标题和封面是适配遗漏。现在按卡片归属提取作者，分类保留多作者；网站筛选标签明确 `status=0` 为连载、`1` 为完结、`2` 为短篇，短篇不伪造成连载或完结。排行榜热度保存在 `metadata.heat`，不当作已验证的阅读次数。推荐区当前确实只提供标题与封面，不逐本补抓详情。

源工厂用 `list_display` 声明作者行及状态/热度/更新时间行。后续平台新增字段时，源可映射规范字段或有界 `metadata` 并修改展示配置；只要宿主已支持该契约，无需按平台修改 UI。完整字段与限额见[契约](CONTRACT.md#列表展示配置宿主-0108-起可选)。

## 稳定身份比排序更重要

作品使用 path_word；章节用站内 UUID/id。章节插入或分组顺序变化不改变已有 `_id`。结果放在 `episodes`，显示顺序由数组与 sort_index 决定。读取图片时拿到 `c_<chapter_id>`，剥离前缀后请求站内章节。

当前 App 路径优先 default 分组，然后其他分组；组内按 ordered 与 UUID 排序、去重。网页路径按分组和返回章节顺序映射。若发现 App/网页标识不一致，先验证历史兼容，不能简单换 ID 让旧下载或续读失去归属。

## 图片、地址与错误

- 平台私有代码仍读取 URL 字符串数组；1.4.0 的 API v3 入口返回 index/resource 的完整 PageList。宿主的统一运行边界与图片请求链负责实际读取，已发布 API v2 包仍保留 0.10.4 起的图片归一化兼容。
- 网站、API、CDN 分别处理；网站与 API 提供独立设置。图片携带所需 Referer，HTML/API 请求按协议处理自己的头。
- 只接受预期 HTTPS 基址与安全站内标识；相对图片地址归一化。
- 当前加密响应包含 IV 与十六进制密文；解析、长度和 JSON 都校验。协议变化应失败并留下短诊断，不返回空列表掩盖问题。
- 未登录时网站章节失败后才使用匿名 App 兼容路径；两条路径都失败必须明确报错。不能不断探测未知接口。

## 测试应该证明什么

现有私有测试在 `test/extensions.lua` 与 `test/extensions_live.lua`。未来导出时仅带对应脱敏样例、源专属断言和通用检查器，不带宿主私有设备资料。

离线至少验证：推荐排除最新区、分页列表、搜索字段、CBC 已知向量、全部章节分页、图片完整性、稳定章节顺序以及 HTTP/结构错误。通用 fixture 检查器不理解该源所有语义，需要补充源专属断言。

2026-10-21 的一次在线记录为推荐 12、最新 60、搜索 12、已知作品 117 话、首话 107 张图片与首图下载通过。这是样本证据，不代表全站、账号能力或所有作品通过。后续修改必须记录新的日期、源版本和实际样本，不能继承这次在线结果。

## 登录与账号适用范围

解析参考 [Aidoku 源](https://github.com/Aidoku-Community/sources/tree/main/sources/zh.copymanga)；历史 App API 域名与 [fumiama 客户端配置](https://github.com/fumiama/copymanga/blob/main/app/src/main/res/values/strings.xml)一致，不是从 Rakuyomi 移植的账号接口。网站认证需要核对当前登录页脚本，不能据此假设 App 端认证兼容。

当前源使用网站的账号密码登录接口及用户资料接口校验会话。只加密保存绑定网站 origin 的 token，不保存密码。站内 HTML/JSON 请求携带该会话；图片 CDN 和匿名 App 兼容接口不携带。更换网站地址后旧会话不可复用。401 清除会话；210 可能表示账号错误或平台访问限制，不能统一翻译为账号不存在，也不自动反复重登或规避限制。

注册由用户在当前官网登录页完成，插件没有注册功能；未查到独立的开发者账号注册流程，也没有证据证明网页登录账号或 token 可用于历史 App 节点。2026-10-21 网站资料及同源章节/图片曾验证成功，网站 token 调用 App 用户接口返回 401，两组账号的 App 登录未成功；随后官网出现明确的临时登录限制，最终账号复验未通过。不能把本地会话字段或匿名阅读成功当作账号验收通过。

已登录时章节与图片列表坚持网站链路，失败直接返回，不降到匿名 App 接口。保留匿名兼容路径不代表已支持 App 登录或评论；1.3.0 的账号收藏只使用同源网站会话，不把网站 token 发往 App 节点。

## 1.2.0 匿名验收

2026-10-21，空 KO_HOME 下 26 项通过，无账号尝试。推荐、最新与搜索第二页、中文搜索、68 个分类、分类分页/人气排序、八类排行均通过；本地收藏增删和列表复用宿主逻辑。样本 onepoint 为 117 话、首话 107 张图片，封面与首尾图实际下载并校验格式。请求检查确认无 Authorization/Cookie、账号端点或 POST，结束后无会话。账号、只读评论和账号收藏不在本次通过范围。

## 1.3.0 网站账号收藏

2026-10-21 重新读取官网详情和个人书架脚本，按公开协议独立实现：

- 列表：同源 `GET /api/v3/member/collect/comics`，每页 12 部、offset 分页、free_type=1、最近收藏或最近更新排序；条目取嵌套 comic 的 path_word/name/cover。总量、offset、条目与空页分别校验，失败不能伪造成空收藏。
- 增删：从详情页 `.collect` 的 onclick 读取服务器 UUID，以 `POST /api/v2/web/collect` 的 comic_id 与 is_collect=1/0 设置状态。作品身份始终使用 path_word，不能用 UUID 替换历史、下载或本地收藏键。重复添加或移除先检查页面当前状态，不反向 toggle。
- 详情：登录时从同源 HTML 的书架按钮读取 isFavourite；未登录不混入账号状态。凭据仅发给配置绑定的网站，401 清除会话；响应错误不输出完整个人数据。
- 宿主：继续使用 API v2、最低 0.10.0，不新增宿主接口或平台 UI；`access.favorites=login`，共享主页和详情按现有逻辑切换线上/本地收藏。

来源为官网 [详情脚本](https://s3.mangafunb.fun/static/websitefree/js20190704/comic_detail20240918.js)及[个人书架脚本](https://s3.mangafunb.fun/static/websitefree/loginStatic/js/person.1b8bbe2f18a97f2437e5.js)。未复制脚本实现；测试使用最小虚构作品和会话，包含空列表、损坏分页、重复增删、状态变化、失败与过期。离线通过不能代替真实账号验收。

只读评论仍未实现：当前详情页无评论区，当前 API 的历史章节吐槽 `/api/v3/roasts` 返回 404；没有将章节吐槽伪装为整部漫画评论，也不启用空实现。后续需要平台提供实际可用且语义明确的接口。
